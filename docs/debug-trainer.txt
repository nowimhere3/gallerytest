### 1. CONTEXT AND ARCHITECTURAL PURPOSE


In multi-repo or legacy-vs-sandbox codebases, standard unit tests and static code reviews frequently fail to identify the root cause of missing or mismatched data. This happens because the breakdown rarely occurs in isolated business logic; instead, it occurs at the volatile intersection of:
- OS-level directory selection and permission boundaries.
- Browser-native file API primitive differences (e.g., HTML5 `<input webkitdirectory>` vs. Chromium Native File System Access API `FileSystemDirectoryHandle`).
- Platform-level MIME sniffer variances and empty string default assignments.
- Asynchronous stream traversal, iterator terminations, and unhandled promise rejections.
- State-reconciliation, deduplication keys, and token-cancellation lifecycle hooks.


Standard debugging strategies often resort to trial-and-error code modifications, which introduce regression risks, pollute codebases, and mask underlying architectural flaws. The **Dual-Repo In-Browser Parity Method** replaces guesswork with strict, boundary-level runtime measurement, source code verification, and non-destructive telemetry.

### 2. THE FIVE FOUNDATIONAL OPERATIONAL TENETS

#### Tenet II: Strict Separation of Diagnosis and Remediation
- **Rule:** Under no circumstances shall you propose, draft, or implement application code fixes, refactoring, or patches until the root cause has been proven across all pipeline boundaries.
- **Execution:** When presented with a discrepancy (e.g., Pipeline A has 1,421 items, Pipeline B has 1,760 items), your sole objective is *forensic isolation*. #### Tenet III: Strict Privacy-Preserving Telemetry & Anonymization
- **Rule:** When inspecting, logging, or reporting on local user files, personal directories, or sensitive datasets, you must NEVER output, log, or store raw filenames, file titles, folder paths, raw URLs, or media contents.

#### Tenet IV: Content-Based Physical Identity Hashing
- **Rule:** Never use string paths (`relativePath`, `webkitRelativePath`, or absolute paths) as the primary key to evaluate physical identity across different ingestion pipelines.
- **Execution:** Different browser APIs represent identical physical files using fundamentally different path prefixes (e.g., HTML inputs prefix the selected top-level folder name like `2/Staging/File.png`, whereas File System Access handles relative paths start inside the handle root like `Staging/File.png`).
- **Identity Hash Formula:** To determine whether two items across Pipeline A and Pipeline B represent the exact same physical asset on disk, compute and evaluate physical content keys:
  $$\text{PhysicalKey} = \text{lowercase}(\text{file.name}) + \text{"\_"} + \text{file.size} + \text{"\_"} + \text{file.lastModified}$$
  *Note:* While `file.name` is used internally within the runtime script to form the cryptographic or string signature key, it must be stripped before printing output to the console or chat.


#### Tenet V: Symmetric Non-Biased Evaluation (No False Parity)
- **Rule:** Do not assume that Pipeline A is the "correct" baseline and Pipeline B is "broken," or vice versa.
- **Execution:** Evaluate both pipelines with total architectural neutrality. If Pipeline A produces 1,421 items and Pipeline B produces 1,760 items, your objective is NOT to arbitrarily force Pipeline B down to 1,421 or push Pipeline A up to 1,760. Your objective is to explain *why* each pipeline makes different validation, discovery, or rejection decisions about the exact same physical data on disk.

#### STAGE 1: RAW DISCOVERY BOUNDARY ($S_1$)
- **Definition:** The lowest-level physical handoff between the operating system, the browser C++ thread, and the JavaScript runtime.
- **Platform Primitive Mechanisms:**
  - *HTML5 `<input webkitdirectory>`:* Produces a flat, synchronous `FileList` array containing all unhidden files in the selected directory tree.
  - *Chromium File System Access API (`FileSystemDirectoryHandle`):* Yields an asynchronous stream iterator (`for await (const entry of dirHandle.values())`) that recursively traverses nested directory handles.
- **Critical Failure Modes in Stage 1:**
  - *Silent Iterator Termination:* Unhandled permissions errors, broken symlinks, or OS lock errors inside a nested directory handle can throw an exception inside `dirHandle.values()`, killing the entire recursive loop prematurely.
  - *Browser API MIME Assignment:* Chrome’s native `webkitdirectory` parser assigns `File.type = ""` (empty string) to `.ts` (MPEG transport stream) files. Conversely, FSA handle extraction via `handle.getFile()` queries an internal OS extension map, assigning `File.type = "video/mp2t"`.


#### STAGE 2: PROVIDER FILTERING BOUNDARY ($\Delta_{\text{Filter}}$)
- **Definition:** The intermediate transformation layer inside the provider class (e.g., `LocalFileInputProvider.js` or `FileSystemAccessProvider.js`) before items are passed to object factories.
- **Mechanisms:**
  - In-memory regex filtering (skipping `.DS_Store`, `.git`, or hidden directories).
  - Lifecycle token cancellation (`if (token !== this.#loadToken) return;`).
  - Directory depth caps or custom provider-level file extension whitelists.
- **Critical Failure Modes in Stage 2:**
  - Stale load cancellation: A rapid React re-render invalidates `#loadToken` mid-scan, causing the provider to silently drop the remaining batch of discovered items.
  - Asynchronous race conditions where concurrent scans overwrite provider buffer arrays.


#### STAGE 3: FACTORY & MODEL CREATION BOUNDARY ($\Delta_{\text{Factory}}$)
- **Definition:** The domain instantiation function (e.g., `createMediaItem(file)` in `media-item.js`) that converts raw browser `File` primitives into application domain models (`MediaItem`).
- **Mechanisms:**
  - Strict type checking, MIME validation, aspect ratio checks, and metadata parsing.
  - Factory functions return `null` or throw errors when validation rules fail.
- **Critical Failure Modes in Stage 3:**
  - *The MIME Guard Trap:* A factory function enforcing `if (!file.type.startsWith('image/') && !file.type.startsWith('video/')) return null;` will silently reject all `webkitdirectory` `.ts` files (because `File.type === ""`), while accepting identical `.ts` files loaded via FSA (because `File.type === "video/mp2t"`).
  - Lack of extension fallbacks when `File.type` is empty or generic (`application/octet-stream`).


#### STAGE 4: STATE & SESSION COMMIT BOUNDARY ($\Delta_{\text{State}}$)
- **Definition:** The state management layer (Zustand, Redux, React `useState`, IndexedDB) responsible for committing created domain models into global session memory.
- **Mechanisms:**
  - Deduplication indexing using Map/Set keys (e.g., `map.set(item.id, item)`).
  - Batching, store merging, and collection slicing.
- **Critical Failure Modes in Stage 4:**
  - *Deduplication Collisions:* If the ID generation function (`MediaItem.id`) uses an unstable string hash (such as full relative paths containing root folder name variances like `2/Folder/a.jpg` vs `Folder/a.jpg`), items may fail to match or mistakenly overwrite valid items in state.
  - Race conditions during state hydration where prior batch commits overwrite newly created media arrays.


#### STAGE 5: FINAL RENDERABLE / OUTPUT STATE ($S_5$)
- **Definition:** The actual collection of items rendered into the DOM or presented to the user view component.
- **Mechanisms:**
  - Virtualized list windowing (e.g., `react-window`, `tanstack-virtual`).
  - Active UI filters (e.g., "Show Images Only", date range sliders, search inputs).
- **Critical Failure Modes in Stage 5:**
  - UI pagination limits masking the true size of the underlying state store.
  - Active frontend view filters hiding specific media formats without logging to console.

### 2. THE FIVE MANDATORY RULES OF DEVTOOLS DIAGNOSTIC SCRIPTS


Every DevTools diagnostic snippet you design or request must strictly comply with these five engineering rules:


#### Rule I: Zero Application Mutation (Read-Only Idempotency)
- **Constraint:** Diagnostic scripts must NEVER modify application source code, mutate React/Vue component state, overwrite global window prototypes, alter DOM elements, or trigger state-mutating API requests unless explicitly instructed.
- **Purpose:** The diagnostic must observe execution behavior without altering the state being measured. Running the script 1 time or 100 times must yield identical, non-destructive results.


#### Rule II: Strict Privacy Bounding & Automated Data Scrubbing
- **Constraint:** Scripts must NEVER print raw filenames, absolute folder paths, relative paths, URLs, DOM titles, or media content strings to the browser console or return them in data payloads.
- **Execution:** All items evaluated by a diagnostic script must be programmatically scrubbed into aggregate technical metadata prior to output.

  - **Scrubbing Pattern:** If path structures must be logged to evaluate relative depth or prefix differences, sanitize string labels into generic markers (e.g., `[ROOT]/[DEPTH_1]/[ANONYMOUS_FILE]`).


#### Rule III: Physical Identity Signature Generation
- **Constraint:** Scripts must evaluate item identity across different pipelines using physical content signatures rather than string paths.
- **Signature Formula:**
  $$\text{PhysicalKey} = \text{item.name.toLowerCase()} + \text{"\_"} + \text{item.size} + \text{"\_"} + \text{item.lastModified}$$
- **Execution:** Compute `PhysicalKey` internally within JS memory maps to match identical physical files across pipelines. Scrub the key before outputting summary data tables.


#### Rule IV: Browser Security & User-Gesture Compliance
- **Constraint:** Browser security models require an active user gesture (e.g., a click event) to trigger file system picker APIs like `window.showDirectoryPicker()`. Rule V: Window Memory Persistence (window.__DIAGNOSTIC_CACHE)
Constraint: Raw file scans or pipeline traversals can be computationally expensive. Diagnostic scripts must persist their intermediate aggregate results to global memory (window.__DIAGNOSTIC_CACHE) rather than discarding them.

---### 1. THE PURPOSE OF DUAL-SOURCE FORENSICS


Runtime telemetry (Part 3) tells us *where* data drops across the 5-Stage Pipeline Model ($S_1 \to \Delta_{\text{Filter}} \to \Delta_{\text{Factory}} \to \Delta_{\text{State}} \to S_5$). Static code forensics tells us *why* it drops.

- You must compare function implementations side-by-side to identify subtle conditional branches, missing fallback handlers, platform primitive mutations, and unhandled asynchronous exceptions.

### 2. THE 8-STEP CALL-CHAIN TRACING PROTOCOL


For every data ingestion pathway under investigation, you must reconstruct and compare the complete 8-step execution call chain in both repositories:
[1. User Gesture] ──> [2. UI Component Listener] ──> [3. Service Orchestrator] ──> [4. Provider Instantiation]
│
[8. View DOM Render] <── [7. State Commit Store] <── [6. Factory Validation] <── [5. Raw Discovery Loop]




#### Step 1: User Gesture Event
- *Inspection Focus:* What DOM event triggers the ingestion? (e.g., `<input type="file" change>` vs `<button onClick>` invoking native browser picker APIs).
- *Divergence Point:* Check if the gesture handler enforces specific file extension masks or mime filters directly on the picker options.


#### Step 2: UI Component Event Listener
- *Inspection Focus:* Which React/Vue component captures the event, and what props or state setters are passed into the controller layer?
- *Divergence Point:* Look for unhandled component unmounting or state resets that interrupt active scans.


#### Step 3: Controller / Service Orchestrator
- *Inspection Focus:* How does the application decide which provider or strategy to invoke?

  // Generate deterministic PhysicalKey hash (No explicit text preserved)
  const physicalKey = `pk_${Math.abs(
    `${rawIdentifier}_${size}_${lastModified}`
      .split('')
      .reduce((acc, char) => (acc << 5) - acc + char.charCodeAt(0) | 0, 0)
  ).toString(16)}`;


  // Extract non-sensitive extension
  const ext = rawIdentifier.includes('.') 
    ? `.${rawIdentifier.split('.').pop().toLowerCase()}` 
    : 'NO_EXT';


  // Return purely technical primitives to console.table
  return {
    physicalKey,
    extension: ext,
    mimeType: item.type || item.mime || 'UNKNOWN',
    sizeBytes: size,
    state: item.status || item.state || 'OK'
  };
};
